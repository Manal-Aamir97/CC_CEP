# Human-written cloud configuration dataset

Goal: a public dataset of cloud configurations **written by people, not generated by AI**, used to compare configuration accuracy with and without LLM assistance. Checked on 2026-10-28.

**Test for "human, not AI":** the configurations must have been collected before AI coding tools were widely used. ChatGPT was released on 30 November 2022. GitHub Copilot entered technical preview in June 2021 and became generally available in June 2022.

## Recommended: Verdet et al. (2025), AWS Terraform sample

| DB-04 RDS storage encrypted | Yes (CKV_AWS_16) |

So the plan is to score the original Terraform files with **our own validator**, so that every rule is measured the same way as in the rest of the study. Their Checkov results then serve as an independent cross-check.

### Limits to handle and report

1. **The Terraform files are not in the package.** Their scripts downloaded each project, scanned it, and deleted it. Each project must be fetched again from GitHub and **pinned to its last commit before 14 October 2022**. Using today's latest commit would bring in post-2022 code, which might be AI-assisted.
2. **Attrition:** some of the 401 repositories may have been deleted or made private since 2022. Report how many could be recovered.
3. **No licence file** in the replication repository, and the projects carry their own licences. Cite the paper, use the data for analysis, and publish only aggregate results and our own scripts, not copies of other people's code.
4. **Intent is unknown.** A real project may open a bucket or a port on purpose (for example, a public website). Score findings as deviations from the CIS / Security Hub baseline, and report public-access rules separately from rules where intent rarely matters (encryption, logging, versioning, backups, admin ports open to the internet).
5. **Strictest "no AI" claim:** Copilot was generally available from June 2022, so "before ChatGPT" is not "before every AI tool". For a stricter subset, also pin each project to its last commit before 29 June 2021 (the start of the Copilot preview) and report both.

## Plan: used alongside the user study

The user study stays the main comparison: participants with LLM assistance against participants without it. The dataset adds two things.

### Use 1: real-world human baseline (no LLM involved)

Verdet et al. already published, for every project, which Checkov checks each resource passed or failed in October 2022 (`results.csv`). [`checkov_to_rules.json`](checkov_to_rules.json) maps those checks onto 7 of our 15 rules, and records:

- which mappings were confirmed in Checkov's source code;
- which checks are deliberately left out. For example, `CKV_AWS_260` flags port 80 open to the internet, which our web-server tasks require.
- which of our rules their scan does not cover.

`baseline.py` turns this into a human error rate per rule: the share of resource checks that failed, and the share of projects with at least one failure. **No project code needs downloading for this.**

In Section 5 this answers: "How often do real engineers, without an LLM, make the mistakes our tasks test?" The numbers come from Checkov, not our validator, so they are comparable in kind but not identical in definition. The report must say so.

### Use 2: Step 7 offline test set from real human configurations

1. `select_cases.py` picks 30 projects (with reserves). For each resource type: 7 whose 2022 scan failed a mapped check and 3 that passed. It uses a fixed seed, so the choice can be reproduced.
2. `fetch_files.py` pins each chosen project to the last commit on its default branch before 14 October 2022. That matches the commit Verdet et al. scanned, and is before ChatGPT. It then downloads only that commit's `.tf` files. With `--cutoff 2021-06-29` it builds the stricter pre-Copilot version instead.
3. Two researchers convert one resource per project into our schema by hand, following [`cases/README.md`](cases/README.md): copy values exactly, never guess, and drop a rule rather than assume. `check_cases.py` checks every case and traces it back to the exact repository, commit, file and lines.
4. For each case, record:
   - the validator's score of the configuration as the human wrote it (**without LLM**);
   - the score after applying exactly what the LLM recommended (**with LLM**);
   - errors the LLM caught, errors it missed, and advice that was wrong.

   This is the dataset-level "with vs without LLM" comparison. It also tells Section 5 whether participants' mistakes in the assisted condition could have come from bad advice.

### Commands (from the repository root, in order)

| Step | Command | Downloads |
|---|---|---|
| 1 | `python -m dataset.fetch_verdet` | 3 files from github.com/averdet/master-terraform-sec-adoption, about 720 kB (`dataset_repo_metadata.csv` 14.6 kB, `results.csv` 687.7 kB, `policies-aws-final.csv` 17.0 kB); 1 API request |
| 2 | `python -m dataset.baseline --show-policies` | none. Prints Verdet et al.'s description of each mapped check, for a human to confirm the mapping. |
| 3 | `python -m dataset.baseline` | none. Writes `results/baseline.md` and `baseline.json`. |
| 4 | `python -m dataset.select_cases` | none. Writes `results/case_candidates.csv`. |
| 5 | `python -m dataset.fetch_files` | only `.tf` files of the 30 main candidates (≤ 300 files, each ≤ 1 MB per project; usually a few MB in total); 2 API requests per project, 60 in total, which is exactly the hourly limit without a token |
| 6 | `python -m dataset.fetch_files --fill-gaps` | only the reserves needed to replace main projects that could not be fetched |
| 7 | `python -m dataset.worksheets` | none. Writes one worksheet per project to `results/worksheets/`, listing relevant resources with file and line numbers. It quotes no code. |
| 8 | (manual) write `cases/case_C01.json` ... | none |
| 9 | `python -m dataset.check_cases` | none. Writes `results/cases_summary.md`. |

Tests (offline, no downloads): `python -m unittest dataset.test_dataset -v`.

Downloaded files go to `dataset/raw/`, with a manifest recording the source commit and SHA-256 of every file. They are other people's code, so they are used for analysis only and not redistributed. Only aggregate results and our own scripts go into the report.
